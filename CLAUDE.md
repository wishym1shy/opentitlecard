# CLAUDE.md — working habits for OpenTitlecard

Read this first. It describes the app, the rules for changing it, and how to work with the maintainer.

## What this is

**OpenTitlecard** (repo `wishym1shy/opentitlecard`) is a single-file, no-dependency HTML app that renders TikTok-style titlecards for social video to a transparent PNG. See `README.md` for the user-facing description.

- **One file:** `index.html` holds all markup, CSS and JS. Keep it that way. No bundler, no framework, no CDN or network requests.
- `docs/screenshot.png` is the README image. Regenerate it only when the UI visibly changes.
- `LICENSE` is MIT.
- `CHANGELOG.md` lists what changed per version, newest first.
- **App icon:** inline in `<head>`, like everything else: an SVG data URL for the tab (a capital O with a superscript t, drawn as shapes, white on a cyan/blue/green gradient in a squircle) and a 180 × 180 PNG data URL as `apple-touch-icon` (full-bleed, because iOS rounds the corners and doesn't take SVG). If the design changes, regenerate the PNG from the SVG so they match.
- **Name:** the project was called `opentok-titlecard` until the rename. Storage keys are `opentitlecard.*`; `index.html` copies any old `opentok.*` values over once (see `migrateOldKeys`). Keep that migration. "OpenTok" is an unrelated, established product, so don't reintroduce the name.

## Product context (why it is built this way)

- **Who it is for:** video editors who need TikTok-style titlecards (white rounded box, bold text, per-line boxes) as a transparent PNG without buying plugins. The workflow target is editors staying inside Premiere Pro; the PNG also works in After Effects, DaVinci Resolve, CapCut and anything else that reads PNGs.
- **Static PNG only.** No animation, pop-ins or video export. Animated templates are a separate, later project (a MOGRT). A MOGRT is a zip of an After Effects project with expression logic and cannot be generated from this HTML app, so don't try to emit one here.
- **Emoji are empty slots, never drawn.** Adobe's text engine can't render colour emoji fonts (they come out hollow and black-and-white), and Apple's emoji artwork is copyrighted and can't be bundled. The editor pastes the real iOS emoji on top in their editor. The slot reserves exactly the right space, and the **Emoji slot** panel gives its size and Position values. Don't "helpfully" draw emoji.
- **Default font is Inter Bold** (open source, SIL OFL; maintainer decision: the default must suit every short-form editor, not any one agency's brand font), **bundled** in `index.html` as base64 (variable font, Latin subset) so it works offline on any computer. It must stay swappable (installed fonts or a loaded file) because clients bring their own. Don't special-case any brand font in the app.
- **Per-word colour and italic are the headline features** that existing templates lack (they colour the whole text block only).
- **Keep the repo neutral.** This is a public, general-purpose open-source tool. Don't put any employer, studio or client names, internal paths, sample client copy or branding in code, tests, docs, commit messages or PRs.

## Git and PR rules (important)

Tooling note: in Claude Code web sessions `gh pr create` fails because GraphQL is blocked. Open PRs with the REST API instead: `gh api repos/wishym1shy/opentitlecard/pulls --input pr.json` (JSON with `title`, `head`, `base`, `body`).

1. **Never push to `main`.** The initial commit was the only exception. Every change goes on a branch (`feat/…`, `fix/…`, `docs/…`, `ci/…`) and reaches `main` through a pull request.
2. **Open a pull request when a branch is ready** (tests pass locally). Don't wait to be asked, and don't open PRs for half-finished work. The PR description says what changed, why, how it was verified, and what could *not* be verified. For geometry changes, include the measurements.
3. **Never merge, approve, or enable auto-merge.** The maintainer reviews and merges every PR, personally. Your job ends at an open PR with green CI.
4. Never force-push, rewrite published history, or delete branches unless asked.
5. Keep commits small and focused, with clear messages. One concern per branch.
6. **Versioning (maintainer decision):** versions are `vMAJOR.MINOR`, and every PR that changes the app adds one to the minor number (v1.31 → v1.32). In the same PR: bump `package.json` and the root entries in `package-lock.json` to `MAJOR.MINOR.0`, update `#appVersion` in the header, and add a `## vMAJOR.MINOR` entry at the top of `CHANGELOG.md` (Added / Changed / Fixed, written for users). `tests/version.spec.js` fails if the three disagree. Docs-, test- or CI-only PRs don't bump. If two PRs are open at once, the one merged second takes the next number when it is updated.
7. Don't commit test output (`test-results/`, `playwright-report/`), scratch scripts, downloaded fonts or exported PNGs. Anything under `docs/` must be intentional.

## CI

GitHub Actions (`.github/workflows/ci.yml`) runs the Playwright suite in headless Chromium on every pull request and every push to `main`. A PR is only ready when CI is green. The maintainer still reviews and merges.

- Tests live in `tests/`: `app.spec.js` (loading, fonts, emoji slots, colour/italic, preview interaction, nudge), `geometry.spec.js` (box rules, descender clearance regression), `wrap.spec.js` (auto-wrap), `nudge-sliders.spec.js` (X/Y nudge sliders), `export.spec.js` (PNG output), `storage-and-presets.spec.js`, `batch.spec.js` (cards, file names, ZIP writer, export dialog), `card-styles.spec.js` (per-card styles, apply preset to all), `batch-file.spec.js` (save/open batch files, untrusted input, no card persistence), `export-dialog.spec.js` (canvas and preset controls in the dialog), `default-font.spec.js` (the bundled default Inter, without loading the test font), `style-controls.spec.js` (slider reset buttons, stretch/squish), `font-warning.spec.js` (the ⚠ in the family box and its pop-out), `punctuation.spec.js` (part-of-a-word highlight and click-to-narrow), `remembered-fonts.spec.js` (fonts kept in IndexedDB, Reset to Inter, Forget), `undo.spec.js` (undo/redo), `canvas.spec.js` (orientation, 4K limit), `panels.spec.js` (floating panels, Titlecard Properties, first-open layout), `cards-panel.spec.js` (the Cards layers list, icons and ⋮ menu), `card-names.spec.js` (Titlecard N names, rename, two-column import, {name} file names), `fields.spec.js` (sidebar fields: typed values, scrub, hex codes, alignment buttons), `version.spec.js` (version in package.json, header and changelog agree), `app-icon.spec.js` (inline tab and bookmark icons), `zoom.spec.js` (zoom and pan), `safezone.spec.js` (safe zone overlay), `mockup.spec.js` (mock-up background), `leave-warning.spec.js` (the leave-page prompt), `animations.spec.js` (open/close animations), `auto-scale.spec.js` (fitting Scale to a new canvas).
- `tests/helpers.js` has the shared fixture. It opens the app, loads the pinned Inter font through the app's own **Load font file…** input, and fails any test that logs a page error, console error or dialog.
- Dependencies are **dev-only** (`@playwright/test`, `@fontsource/inter`), pinned exactly, with `package-lock.json` committed. The app has no runtime dependencies. Don't add any.
- Keep `window.__tt` (state `S`, layout `L`, `render`, `renderNow`, `exportGeometry`, `draw`, and the batch helpers `cards`, `active`, `batchNames`, `zipStem`, `crc32`, `buildZip`, plus `undo`, `redo`, `history`, `view`, `safezone`, `mockup` and `unsavedWork`) stable. The tests depend on it. If you must change it, update the tests in the same branch.
- **A bug fix needs a test that fails without the fix.** Prove it: break the code on purpose, watch the test fail, restore it.
- Tests assert *rules* (em-based margins, alignment, transparency), not font-specific pixel values, so they hold on any machine.
- Tests that fail only on CI: check the uploaded `playwright-report` artifact before guessing.

## Architecture in one screen

- **State** `S` holds text plus per-UTF-16-unit `colors[]` and `ital[]` arrays, per-line `nudges[]`, and all style settings.
- **`layout()`** works in design units (px at 1080p-class, `scale = max(W,H)/1920`). It returns lines, items (text runs and emoji slots), word boxes for hit-testing, and the per-line box rectangles.
- **`wrapItems()`** (called from `layout()` once per manual line) does optional greedy word-wrap when `S.wrap` > 0. `S.wrap` is the whole card width, padding included. A word is a run of non-space pieces, so an emoji slot typed right after a word stays glued to it. Styled runs are rebuilt after splitting so color and italic survive. Breaks happen only at spaces.
- **`draw()`** paints from the layout at any scale. Preview and export use the same function, so they match. Geometry is computed in units and multiplied by `u`; shadows and letter-spacing are set in device pixels.
- **`roundedUnion()`** builds the outline of the overlapping per-line rectangles and rounds every corner (convex and concave) with `arcTo`.
- **Emoji** are detected with `Intl.Segmenter` plus a regex (`Emoji_Presentation`, VS16, regional indicators, keycaps, ZWJ). `™ © # 1` stay text. Emoji are never drawn, only reserved as slots.
- **`italicShift()`** fixes a slanted word looking too close to the next word and too far from the previous one: a slanted glyph keeps its baseline but leans right as it rises. It measures how far the ink of a fixed reference glyph (`H`) moves when italic, and `layout()` shifts every italic run left by that amount (run `x` and word boxes, so highlight and click targets match what is drawn). A fixed glyph is deliberate: measuring each word's own ink overshoots on words with tall letters such as `Titlecard`.
- **Nudge controls:** `S.nudges[i] = {x,y}` is the single source of truth. Each line row has three controls per axis (slider resting at 0, a draggable X/Y scrub label, and a number field) and all read and write it through `setNudge()`. The slider covers +-200, the number field accepts any value, and `syncNudgeRows()` keeps them in step. Number inputs carry `data-i`/`data-a`; sliders and labels use `data-slider`/`data-scrub` plus `data-line`, so the two kinds of selector never collide. Alt-drag in the preview writes the same state.
- **Cards (batch):** the active card always lives in `S` (text, `colors`, `ital`, `nudges`), so every existing control and test keeps working. `cards[]` holds a copy of each card; `selectCard()` stashes `S` into `cards[active]` and adopts the next one. Style is shared by default: `sharedStyle` is what every card without its own `card.style` uses, and a card can carry its own copy of the `CARD_STYLE_KEYS` (canvas/crop keys stay global, they belong to the export). Whichever style applies to the active card is what `S` holds, so the style controls edit "the card in front of you"; `persistStyle()` always saves the shared one so a card's own style never becomes what the app opens with. "Apply preset to all" sets `sharedStyle` and drops every card's own style. `withCard(card, fn)` swaps a card into `S`/`L` for the duration of `fn` (thumbnails and export) and always restores the active card. `exportCanvas()` is the single place a card is painted at export size, used by both Download PNG and the ZIP.
- **Cards panel:** laid out like a layers panel. Above the list (`.layerbar`): the card count, then icon buttons for the set as a whole (*Add from list*, *New set*). The set's file actions are in the File menu, not here. The list (`#cardList`) sits in a solid box (`.layers`) whose footer holds the card actions as icons (Add, Duplicate, Move up/down, Delete). Icon buttons have no text: every one needs an `aria-label` and a `title`. Up/Down in the list select the previous/next card; `selectCardInList()` rebuilds the list at once and moves the focus to the new row (the rebuild would otherwise drop it), and does nothing for the card already selected. A focused card row doesn't block Space+drag panning (`spaceFree()`). `#cardDel` says *Clear card* in its label when only one card is left.
- **Card names:** every card has a `name` (in `copyCard()`, so it rides along in undo and batch files as `m`). New cards are `Titlecard N`: `nextCardName()` takes one more than both the highest `Titlecard N` in the batch and the number of cards, so no number is reused and the first card of a fresh page (or of *New batch*) is `Titlecard 1`. `stash()` keeps the active card's name (S has none). Duplicate gives a default-named card the next number and any other name `"<name> copy"`; Clear keeps the name. Rows show the name with the text's first line under it; double-click or F2 renames in place (`renameCard()`, `#cardRename`: Enter or blur keeps, Esc cancels, empty keeps the old name, Enter during IME composition is ignored, recorded for undo). Ending a rename swaps only the box back for its row (`cardRow()`) and marks the list up to date (`cardListState().sig`), never rebuilding the list, so the click that ended it (on the text box, another card) still lands. `cleanName()` is the one check for names from the rename box, a pasted list or a file (one line, no control characters, `MAX_NAME` 120). *Add from list* reads two columns, `name<Tab>text` as pasted from a spreadsheet. In line mode a paste containing a tab is parsed by `tsvRows()` like a spreadsheet copy: a cell holding a line break comes wrapped in quote marks (inner quotes doubled) and is unwrapped, a cell that merely starts with a quote mark is kept as typed, and an empty text cell stays empty. Block mode uses `listRow()` (the tab on the block's first line); a line without a tab is just the text, as before. `decodeBatch()` names cards from files saved before names existed by the same rule. In the export pattern `{name}` is the card's name (`batchNames(…, cardNames)` fills `{n}` and `{name}` in one pass; a pattern with either gets no number appended), and the dialog's *Name files after the cards* sets the pattern to `{name}`.
- **Confirmations:** anything that throws work away (apply preset to all, dropping a card's own style, *New batch*, and *Open batch file…*) asks first through `confirmAction({title,message,ok})`, an in-app `<dialog id="confirmDlg">` that resolves true only for the confirm button; Cancel and Esc mean no. The buttons resolve it directly (`answerConfirm()`), not through the dialog's `close` event, which fires a task later: a test that sees the dialog gone must also see the answer applied. Never use the browser's `confirm()`/`alert()` for this (the test fixture fails any browser dialog). Tests answer it with `confirmDialog(page, accept)` from `tests/helpers.js`.
- **Batch export:** **Export all N as ZIP…** (`#batchOpen`, its label carries the card count; *Export as ZIP…* for one card) sits in the Export panel, right under Download PNG as an equal choice (`.exportpair`: same style, same size; maintainer decision on #61: it lives in the Export panel, seen once that panel is open), and is the only button that opens the dialog. `batchNames()` turns the pattern (`{n}` token) into unique file names; `{set}` (the set name, or `titlecard` while untitled: `setForFiles()`) is filled first by `withSet()`/`batchPattern()`, for the PNG names and the ZIP name alike. The default pattern is `SET_PATTERN` (`{set}-{n}`; maintainer decision: files are named after the set by default), and a stored pattern equal to the old default `titlecard-{n}` (saved whenever the dialog opened, so not a choice) is read as the new default. Thumbnails carry the checkerboard on the canvas itself, inside a plain box, so the canvas's shape shows. A thumbnail of a card that will be exported is a `button.thumb` that opens the export preview `#pvDlg` (a second modal over the export dialog): `showPreview(i)` paints the i-th exported card with `withCard(card, exportCanvas)` at full size, titled with its file name from `batchFileNames()` and "i of n"; ‹ › and ← → Home End move, stopping at the ends (no wrap); Esc closes only the preview and focus returns to the thumbnail; `buildZip()` writes a stored (uncompressed) ZIP with its own `crc32()`; no library, no network. Empty cards are skipped and don't use up a number. The dialog is a native `<dialog>`; its naming settings persist under `opentitlecard.batch`. It also holds copies of the canvas controls (ids `x_<key>`, for `DIALOG_KEYS`) bound to the same `S` keys as the Export panel (`syncControls()` keeps both in step and `fillBatchGrid()` rebuilds the thumbnails), and a preset picker whose *Apply to all cards* shares `applyPresetToAll()` with the panel button. A canvas over the 64M-pixel limit is flagged up front and disables the download.
- **Bundled Inter:** the font data lives in `<script type="text/plain" id="interFont">` (base64 woff2, preceded by an HTML comment holding the OFL text). `loadBundledInter()` registers it as the family `OpenTitlecard Inter` (never as `Inter`, so it can't shadow an installed Inter), and `fontStack()` puts it right after `"Inter"` for the Inter family only: an installed Inter wins and everyone else falls through to the bundled copy. `bundledState` is `pending`/`ready`/`failed`; `fontAvailable()` is the one "is this family usable?" check (chip, ⚠ warning, export dialog) and treats `pending` as usable so the warning doesn't flash, but `failed` as missing so the app stays honest. Tests that must exercise the bundled path regardless of the machine use the `NO_SYSTEM_INTER` init script in `default-font.spec.js`.
- **Default preset:** its name is stored under `opentitlecard.defaultPreset`. It applies on **first load only** (maintainer decision on #15): at startup, if there is no saved `opentitlecard.style` yet, `applyStyle()` copies the preset into `S` right after `S` is built and `persistStyle()` keeps it as the last-used style. Once any style is saved, the last-used style wins on later loads. Deleting a preset clears it if it was the default.
- **File menu and set name:** the toolbar ends with `#setName` (the set's name, default `SET_UNTITLED` *Untitled set*; `setSetName()` runs it through `cleanName()`, Enter keeps, Esc restores) and `#fileMenuBtn` (*☰ File*), which opens the popover `#fileMenu` (`role=menu`): *New set* (`#setNew`), *Open set…* (`#batchOpenFile`), *Save set* (`#batchSave`), *Save set as…* (`#setSaveAs`), *Import preset* / *Export current style as a preset* (`#presetImport`/`#presetExport`, still `.json`), *Soft reset…* (`#softReset`) and *Reset all…* (`#resetAll`). Maintainer decisions on #61: the word is **set** everywhere in the UI (code identifiers and the file's `type:'batch'` marker keep "batch" so old files open); the menu is a labelled button, not a bare icon. `placeFileMenu()` puts the menu under its button (above it when there is no room); Esc, click-outside, Tab-out and choosing an item close it; arrows step through items. `kbd[data-keys]` hints show Ctrl+ or ⌘. Ctrl/⌘+S saves (Shift: Save as), Ctrl/⌘+O opens, anywhere including text fields, never behind an open dialog. Dropping a file anywhere (only file drags are taken, so dragging text into fields still works) opens it if its name ends `.opntcd` or `.json`; anything else gets a message. **Saving:** `saveSet(asNew)` writes `encodeBatch()` to `<safeName(setName)>.opntcd`. With Chromium's File System Access (`canPickFiles()`), `setHandle` is the file last saved to or opened from (picker or drop, via `getAsFileSystemHandle()`), Save writes back to it (asking write permission once for an opened file) and Save as picks a new one and takes its name; cancelling the picker saves nothing. Without it, every Save downloads a copy. `openSetFile(file, handle)` is the one open path (input, picker, drop). New set clears `setHandle` and the name. The test fixture switches the pickers off (`fileAccess: false`, so Save downloads); write-back tests set `fileAccess: true` and stub `showSaveFilePicker`/`showOpenFilePicker`. Messages from all of this go to `#fileMsg` in the bottom bar.
- **Resets:** `resetApp('soft'|'all')` asks through `confirmAction()` with `RESETS[kind]`, a message that lists what is cleared and what is kept (`#cMsg` has `white-space:pre-line` for the list), then removes keys and reloads (`resetting` skips the leave-page prompt, since the warning already said the cards go). Soft: `SOFT_RESET_KEYS` (last-used style, which holds the canvas size; safezone, mockup, batch naming, panels, autoScale; and `opentok.style`, which `migrateOldKeys` would otherwise copy back). It keeps presets, the default preset (which then applies again, as on a first load), the palette and remembered fonts. All: every `opentitlecard.*`/`opentok.*` key plus the IndexedDB fonts. A new stored key must be added to the right reset and to its message.
- **Batch files:** cards are **never stored in the browser** (maintainer decision on #17: only settings and presets live in `localStorage`; card text can be client copy). `encodeBatch()`/`decodeBatch()` turn the set into a `.opntcd` file (plain JSON; older `.json` files open the same way, since opening goes by content) the user saves and re-opens: `{app:'opentitlecard', type:'batch', v:1, name, active, style, cards:[{t, c, i, n, s}]}` (`name` is the set name, optional on open) with colors/italics stored sparsely. `decodeBatch()` treats the file as untrusted (marker/version checks, per-field validation, caps of 500 cards / 2000 chars / 5 MB, nudges clamped, bad style keys fall back to the current shared style). Opening a file replaces the cards and applies the file's shared style; *New batch* and *Open* ask first only when `batchHasWork()` (more than one card, or text beyond the untouched placeholder, formatting, nudges or an own style). Don't add autosave or any other card persistence. Instead, a `beforeunload` handler makes the browser ask before the tab closes or reloads while `unsavedWork()` is true: `batchHasWork()` and the batch differs from the last file saved or opened (`markSaved()`; compared as `encodeBatch()` without `active`, so a render's bookkeeping or the selected card isn't a change). It is the browser's own prompt, the one exception to "never use browser dialogs"; the test fixture answers it "Leave" (a reload with work is not an error).
- **Stretch/squish:** `S.stretchX`/`S.stretchY` (percent, clamped to 50–200 by `stretch()`) scale the glyphs around each run's baseline origin: `draw()` uses `ctx.scale`, and `layout()` multiplies run widths, word boxes, wrap pieces and the italic shift by `sx`, and cap height and descenders by `sy`. Padding and margins stay in em of the font size, the line pitch grows by the extra cap height (so stacked boxes keep their overlap), and emoji slots stay square and unscaled. At 100% × 100% the layout is unchanged. Outline width is divided by `sqrt(sx*sy)`, so a strongly one-way stretch gives a slightly uneven outline.
- **Reset buttons:** each key in `RESET_KEYS` (Scale, and every Text Settings and Background slider) gets a ↺ button (`data-reset-key`) next to its value, and double-clicking the slider does the same. `resetSlider()` sets the slider to `DEFAULTS[k]` and fires its own `input` event, so saving and per-card styles work exactly as for a drag. `syncControls()` disables a button while its slider is at the default. A new slider in those panels needs adding to `RESET_KEYS`; `style-controls.spec.js` fails otherwise.
- **Sidebar fields:** the sidebar is styled like a design tool's properties panel (flat sections split by hairlines, settings two to a row in `.g2`). Each slider setting is a `.fld` (with `data-name`, which names its ↺ button): a scrub icon (`data-scrub-for="<key>"`), a typed value `#n_<key>`, a visually hidden `#v_<key>` (the formatted value the tests read) and the range `#<key>` as a thin line along the bottom (`--p` fill set by `syncControls()`). The typed value applies on `change` (Enter or blur) or arrow keys, never while typing, and everything goes through `setField()` → the range's own `input` event, so saving, undo and per-card styles have one path. Scrubbing is one step per pixel (Shift = 10); double-click on the icon resets (`resetSlider()`) or sets a position to 0. `#n_wrap` is empty with an "Off" placeholder at 0. Colours have a typed hex code `#hx_<key>` that fires the colour input's `change`. `#align` is a radio group (binding type `rad`); tests pick with `page.check('#align input[value="left"]')`. Nudge axes reuse `.fld` but keep their own handlers (`data-slider`/`data-scrub`/`data-i`). A new slider setting in the sidebar should use the same field markup.
- **Layout:** the left sidebar holds Text (the text box, color and italic tools, then `.fontbox`: font family with its loaders and weight), then **Titlecard Properties** (`#tcProps`, a `details.master` holding the sections Position & Scale (the card offset `offX`/`offY` in `#frameOpts`, then Scale: the font size `S.size`, ids `#size`/`#n_size`, labelled *Scale* because the whole card is in em of it, kept with X/Y by maintainer decision so the mock-up handles are together; it sits outside `#frameOpts`, so in tight crop X/Y and `#posHint` hide, `#posTight` shows and Scale stays), Text Position (line nudges), Text Settings (align and the rest of the type settings), Background and Emoji Slot), then Presets. Titlecard Properties starts closed on every load (maintainer decision: a fresh session opens on the text). Cards, Canvas, Safe zone and Export are floating panels (`.fp`, `data-panel`) in `#panels`, a stack over the right of the preview. Export sits alone at the bottom of the stack (`margin-top:auto`) and is `position:sticky` there, so it stays in view when the stack scrolls (maintainer decision: the screen reads left to right, text, then cards, then export). The stack has `pointer-events:none` (only the panels catch clicks), and while it is shown `.stagebody.with-panels` pads the view so the fitted canvas never sits under it; `renderNow()` fits the canvas to the view's content box. Each panel minimizes to its title (`aria-expanded`); every load starts with only Cards open (`PANELS_MIN`) and minimizing is not remembered. **Panels**, its own pill (`#panelsToggle.pill`) over the top right of the preview with the stack starting below it, hides the stack, which is remembered under `opentitlecard.panels` (a layout preference, not design: not in undo or presets). Keep element ids when moving controls; the tests find everything by id.
- **Open/close animations:** CSS only, at the end of the `<style>` block, inside `@media (prefers-reduced-motion:no-preference)`. Sidebar `<details>` slide via `::details-content` (block-size and opacity); floating panels via `.fpb` height/padding/opacity with `display … allow-discrete`, and `@starting-style` for the opening frame; the ⋮ `.menu` popover and the `<dialog>`s (and their backdrop) fade, using `overlay`/`display` `allow-discrete` so they stay shown until the closing fade ends. Durations `--open` 170 ms / `--close` 130 ms, easing `--ease`. Height animations need `interpolate-size` and sit in an `@supports` for it; without it things open at once. The panels' `@starting-style` rule waits for `.anim` on `<html>` (added two frames after load), so nothing animates at page load. **The test suite runs with reduced motion** (`contextOptions` in `playwright.config.js`) so tests that measure layout right after a click stay deterministic; `animations.spec.js` turns motion back on and samples heights frame by frame (`getAnimations()` doesn't report `::details-content` transitions).
- **Tests and closed sections:** the `app` fixture opens every closed section and panel (`expandUi()` in `tests/helpers.js`) so tests can reach any control; a test that reloads or opens its own page calls `expandUi(page)` again before touching one. Tests of what a user first sees use `test.use({ expandUi: false })` (see `panels.spec.js`).
- **Missing-font warning:** `updateFontWarn()` (called from `updateFontChip()`, so on every render) shows `#fontWarn`, a ⚠ button inside the right of the family box, while `fontReady()` is false. Its message `#fontWarnMsg` is a manual popover (top layer, so it spills over the canvas) placed to the ⚠'s right by `placeFontWarn()`. It pops out on its own whenever a new family/weight goes missing (`warnKey`), including on boot, but not over an open dialog. It fades `WARN_HOVER_MS` (2 s) after the pointer leaves it or the ⚠, or `WARN_IDLE_MS` (5 s) after the first click, key or scroll elsewhere (later actions don't restart it); hover, focus or a click on the ⚠ shows it again. The family name goes in as text, never HTML. `#banner` is now only used for the short "installed fonts loaded" note.
- **Remembered fonts:** a font loaded with **Load font file…** is also stored in IndexedDB (`opentitlecard` / `fonts`, keyed by family: the file's bytes, its name and when it was added; newest `MAX_REMEMBERED` (30) kept, files over `MAX_FONT_BYTES` skipped). `loadRememberedFonts()` registers them all at startup; until it finishes `rememberedState` is `pending` and `fontAvailable()` treats the families remembered last time as usable (their names are also kept in localStorage under `opentitlecard.rememberedFonts`, read synchronously into `pendingFams`), so the ⚠ never flashes for a font about to arrive while any other missing family is still reported at once. A 3 s fallback ends `pending` if the store hangs. Download PNG and the ZIP `await rememberedReady` first, so an export in the first moments never draws a fallback. `window.indexedDB` is read once inside a try (`idb`; reading it can throw in a sandboxed frame) and every store step rejects instead of throwing: without IndexedDB nothing is remembered and nothing breaks. A loaded file named like the default or an installed family ("Inter.ttf") is registered as "<name> (file)", so remembering it can't replace that family. `#fontMem` shows the count with **Forget them** (asks first; the fonts stay usable until the page closes). Remembered families are suggested in the family box (`fillFontList()`, merged with the installed list). The ⚠ pop-out has **Reset to Inter (default)** (`#fontReset`), which sets the family back to `DEFAULTS.family` like any style edit (saved, undoable), so the box and the preview agree again. Fonts are the only thing in IndexedDB; cards are still never stored.
- **Zoom & pan:** `viewState` (`z` = CSS px per canvas px, so 100% is actual size; `x`,`y` = the canvas's top-left in the view; `fit`). `.view` is a clipped window and `placeView()` positions `#previewBox` in it; Fit (the default) centres the canvas in the view's padded area, never above 100%, and follows window and canvas size changes. Out of Fit, a canvas that changes size keeps its centre. Limits are `ZOOM_MIN`/`ZOOM_MAX` (5%–400%); the preview bitmap is `min(1, z*dpr)` of the export size, so it never exceeds the export. `applyPlacement()` keeps at least `PAN_KEEP` px of canvas in view. Ctrl/Cmd+wheel (and trackpad pinch) zooms at the cursor; wheel pans; Space+drag (only when no field or button has focus) and middle-drag pan, in a capture-phase listener that stops the event before the canvas sees it. Ctrl/Cmd + `=`/`-`/`0` zoom and fit. Zoom and pan are a view, not the design: not in undo, presets or storage.
- **Safe zone overlay:** `SAFE_ZONES` holds the built-in zones in a 1080 × 1920 frame (measured from the maintainer's reference diagram: interface bars 250 px top and bottom, the 1420 px safe zone between, and for Reels a side-button column about 200 px wide from y = 1230). `ui` rects are `[name,x,y,w,h]`; `safe` is one outline polygon. A zone with a `draw` function (`igReels16`, *Instagram Reels UI | iPhone 16 Pro*, 1206 × 2622 to match the `1206x2622` canvas preset) paints itself instead of the red/green shading: `drawReelsUI()` draws the Reels screen from plain shapes (generic icons, placeholder avatars and text; no app artwork is bundled) at positions measured from the maintainer's 591 × 1280 iPhone 13 reference screenshot (x scaled by 1206/591; the status bar and tabs by the same factor from the top; everything from the creator and side buttons down kept at the same distance above the nav bar at 2386, as the app lays it out), and its `ui` rects still feed the status line. Last it draws what the phone hides (`IPHONE_CORNER`, `IPHONE_ISLAND`, `IPHONE_HOME`: approximate developer values, since Apple publishes only the screen size): black outside the rounded display, using iOS's continuous corners (`squirclePath()`, filled even-odd against the screen rectangle), the Dynamic Island and the home indicator. The phone body would sit outside the canvas, so it is not drawn. Its navigation bar (y = 2386 to the bottom) is filled solid black first, under the icons, as in the app, so a mock-up background is framed by it (it follows `SZ.opacity` like the rest). It also marks the 9:16 video area (`REELS_VIDEO`: as the iPhone app does, the video fills y = 0 to the nav bar at 2386, so it is 1342 px wide and 68 px of each side is off-screen; measured on the maintainer's iPhone 13 screenshot; drawn clipped to the screen): the tint is painted with `destination-over` so it never tints the card, and the dashed edge and label go on top. Saved kinds are valid if they are `image` or a key of `SAFE_ZONES`. `safeZoneBox()` fits the zone (or the user's image) inside the canvas, scales it by `SZ.scale` and moves it by `SZ.x`/`SZ.y` (canvas px from the centre). `drawSafeZone()` runs in `renderNow()` after `draw()`, so it is preview-only: never put it in `draw()` or `exportCanvas()`. It draws nothing in tight-crop mode. `safeZoneStatus()` checks the card's box (with nudges) against the built-in zones and puts the verdict in `#szFit`, at the right end of the bottom bar `#info` (which starts with the canvas size `#dims`, then the card numbers in `#infoStats`, so the render doesn't wipe it, then `#fileMsg`); `#szStatus` in the panel keeps only notes about the overlay (load an image, tight crop). `__tt.safezone` has both: `fit` and `status`. `SZ` settings are a viewing preference saved under `opentitlecard.safezone` (validated and clamped on load), not part of undo or presets; the user's image (`szImage`) is session-only, like a loaded font.
- **Mock-up background:** the top half of the *Mock-up & safe zone* panel (`data-panel="safezone"`, ids unchanged). `MK` (`on`, `x`, `y`, `scale`, `opacity`) is a viewing preference saved under `opentitlecard.mockup`; the image (`mkImage`) is session-only, since it may be client footage. `mockupBox()` covers the canvas at 100% (`max` of the two ratios, unlike the safe zone's fit), centred, then `MK.x`/`MK.y` and `MK.scale`. `drawMockup()` runs in `renderNow()` right after `draw()` with `destination-over`, so it lands behind the card and guides, and the safe zone is drawn over it. Preview only, nothing in tight-crop mode, never in `draw()` or `exportCanvas()`. It shares `loadView()`, `bindViewSliders()`/`syncViewSliders()` and `readImageFile()` with the safe zone. Their X / Y / Scale / Opacity use the sidebar's `.fld` markup (X | Y in a `.g2`, then Scale, then Opacity): `#n_<id>` typed value, `#<id>` range (hidden with `.noline` on X / Y), `#v_<id>` hidden text, `data-view-scrub` icon (drag = 1 per px, Shift 10; double-click resets); ↺ (`data-<prefix>-reset`) on Scale and Opacity only, like the sidebar. A zone with `frame` (`igReels16`: `1206x2622`) shows a wrong-canvas warning with a *Use … canvas* button (`frameWarning()`, `.usecanvas`) in `#szFit` and `#szStatus` instead of a verdict when the canvas differs; the button dispatches `change` on `#frame`, so auto-scale and undo apply.
- **Auto-scale:** on a real canvas size change (the `frame`/`fw`/`fh` bindings, `setOrientation()`, the custom-size clamp; each passes the dims from before to `autoFit(before)`, which does nothing if they're equal), `autoFit()` sets Scale so the card fits with `AUTO_MARGIN` (20, px at 1080p, maintainer's pick from mock-ups) clear of every edge, offset included (`cardFits()`), before `record()`, so it's one undo step with the canvas change. `fitSize()` binary-searches whole sizes (wrapping makes width non-linear) with `withCard()`; cards without their own style are fitted together on `sharedStyle`, each own-style card alone. `autoMemo` (per style: `'shared'` or `'card:'+name`) remembers `{size, base}`: while Scale still equals what auto-scale set, `base` (the user's choice) is the target again, so it shrinks and grows back but never past the user's Scale; any other value is a new choice. Never runs at load (maintainer decision: a saved Scale is never changed behind the user's back) or in tight crop. `#autoScale` is a saved preference (`opentitlecard.autoScale`, default on), not design.
- **Canvas size:** `MAX_SIDE` (3840) caps every export on each side. `frameDims()` clamps custom sizes to it (the fields clamp on `change`, not while typing), and `tooLarge(g)` refuses a tight crop that would be bigger (Download PNG is disabled with the reason; the export dialog flags it). `setOrientation('h'|'v')` swaps width and height, mapping to the rotated preset when one exists (`CHOICES.frame`), otherwise to a custom size.
- **Undo/redo:** `hist[]` holds up to `HISTORY_MAX` (100) steps; each is a JSON snapshot (`designKey()`: every card, the shared style, and the canvas keys in `GLOBAL_KEYS`) plus the card the change was made on and the text selection. **Every change to the design must call `record(kind)` after it.** Changes with the same non-empty `kind` within `MERGE_MS` (1 s) merge into one step (typing, a slider drag via `'style:'+key`, a nudge via `'nudge'+line+axis`); `kind=''` is always its own step, and `resetSlider()` clears `lastKind` so a reset never merges into a drag. A snapshot equal to the current step adds nothing, so selecting a card or a no-op change is not a step. `restoreStep()` re-adopts the cards and calls `persistStyle()`. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z and Ctrl+Y are handled on `document` (which also blocks the text box's own undo, which knows nothing about colors); fields in `OWN_UNDO` keep the browser's undo, and nothing happens while a dialog is open. The preset library, palette and preview background are not part of history. History is memory-only, like the cards.
- **Part-of-a-word selection:** each word box in `layout()` carries `xs`, the x where each of its characters starts (and its end), measured like the word box itself. The preview highlight paints only the selected characters, with its 4-unit margin only on sides that end at a space. A preview click finds the character (`charAtX()`, which prefers the word box that really contains the point, since a word split by color has boxes side by side) and `clickSelection()` picks the range: the whole word (`wordAt()`) first; clicking that word again while it is exactly selected narrows to the clicked part (`wordParts()`: letter runs, with an apostrophe or hyphen between letters kept in, and the punctuation around them); clicking that part again goes back to the whole word. A caret alone never counts as a selection here.
- **Text edits** use a diff against the old text, biased by the caret, to keep the color/italic arrays aligned.
- **Style validation:** `validStyle()` is the one check for style values the app didn't just set itself: presets (import, load, default, apply to all), the saved style and palette at startup, and batch files (`cleanStyle()` wraps it). A value is kept only with its default's type, finite if a number, hex if a color (`COLOR_KEYS`), and one of `CHOICES` for `align`/`frame`. Route any new source of style values through it, and never put user-supplied strings (such as a font family) into `innerHTML`.

## Calibration (do not change defaults casually)

Box geometry was measured from real reference cards, in em of font size:

- box top ≈ **0.44em** above the cap line (`topPad`)
- box bottom ≈ **0.49em** below the baseline (`botPad`), or **0.24em** below the lowest ink (`clear`), whichever is lower
- side padding ≈ **0.42em**, corner radius ≈ **0.17em**, line pitch ≈ **1.25em**
- each line's box overlaps its neighbours; steps out at the lower line's top, steps in at the upper line's bottom

If you change geometry, re-measure against reference images (alpha channel) and show the numbers in the PR description.

**The reference cards are not in this repo** (they are third-party material). Before changing any calibration number, ask the maintainer for fresh reference images and measure those. Don't tune geometry by eye or from the app's own output, and don't treat "the tests pass" as proof the look is right: the tests check rules, not fidelity to the originals.

## Rules for contributions

- No new runtime dependencies. No network calls. Nothing is uploaded.
- **Never bundle proprietary assets:** fonts, Apple emoji artwork, plugin/MOGRT files, or client branding. Fonts come from the user's machine or a file the user loads. **The one exception is Inter** (SIL OFL), embedded with its copyright and license text (next to the data in `index.html`, and in `THIRD_PARTY_LICENSES.md`). Don't embed any other font, and keep that notice with the font if the data is ever replaced (e.g. a newer Inter).
- Wrap every `localStorage` access in try/catch. The app must work with storage unavailable.
- Chromium-only APIs (`queryLocalFonts`, `EyeDropper`, `ctx.letterSpacing`, `roundRect`) must be feature-detected where practical and degrade gracefully.
- Keep the missing-font warning honest: if the selected family isn't available, say so (the ⚠ in the family box, the header chip, Download PNG and the export dialog).
- Preserve accessibility basics: labels on inputs, visible focus, keyboard-reachable controls.
- Prefer small, readable functions. Comment the *why* for geometry and text-diff code.

## Testing

```bash
npm ci && npx playwright install chromium   # once
npm test                                    # whole suite, ~1 min
npx playwright test --grep "descender"      # a subset
```

Before proposing a change: run the suite, and for geometry changes also render the reference texts and measure box edges from the alpha channel (see Calibration). Report what you verified and anything you couldn't (e.g. a font that isn't installed in the test environment).

## Working in a Claude Code web sandbox (quirks to expect)

- **GitHub access is per session.** If `gh` returns "GitHub access to this repository is not enabled", attach the repo with `add_repo` (use `access: "push"`), and only clone once. GraphQL (`gh pr create`) and org-wide search are blocked; use REST (`gh api repos/wishym1shy/opentitlecard/...`). Some paths, such as the Pages settings API, are blocked too, so ask the maintainer to check those in the web UI.
- **Don't `sleep`.** Foreground `sleep` is blocked. To wait for CI, poll in a loop, e.g. until `gh api repos/wishym1shy/opentitlecard/commits/$SHA/check-runs` reports every run completed.
- **Single-branch clones:** the clone may fetch only `main`. After creating a branch, add a matching `remote.origin.fetch` refspec so the session's stop hook can see the remote branch, and push every branch before ending a turn (the hook flags unpushed commits).
- **Untracked `node_modules`:** a branch that predates `.gitignore` shows it as untracked; put `node_modules/`, `test-results/` and `playwright-report/` in `.git/info/exclude` locally instead of committing anything.
- **Playwright browsers** are pre-installed (`/opt/pw-browsers`); don't run `playwright install` there. Run the suite with `npm test`.
- **Check, don't assume, that PRs merge cleanly.** Before saying two branches are independent, run `git merge-tree --write-tree --name-only A B` (or merge them in a throwaway branch and run the suite). Conflicts have happened in `CLAUDE.md` and `tests/app.spec.js` because several PRs touch the same lines.
- **Prove tests can fail.** For every new test, break the code on purpose (a mutant), watch that test fail, then restore. A test that has never been seen to fail proves little.
- **Unique element ids.** A duplicate `id` once broke the preview-background buttons silently; there is a regression test, but keep ids unique when adding controls.

## Working with the maintainer

- Be candid. If there is a better approach than the one being asked for, say so, even if the maintainer seems invested. They'd rather pivot than build the wrong thing.
- Explain trade-offs briefly, give a recommendation, then proceed. Ask a question only when the answer changes what you build.
- Give real credit when something is done well. Don't pad it.
- Report what you verified and what you couldn't (for example, a font that isn't installed in the test environment).
- Keep summaries short: what changed, how it was checked, and the one next step worth taking.
